# Lab de flujos

## Objetivo

Una página interna, `/lab`, para probar y ensayar la demo sin saltar entre pestañas: muestra la vista del trabajador (marco de celular) y la del pagador lado a lado, y ejecuta los escenarios del pitch con un clic. No forma parte del producto ni del pitch; no se enlaza desde la entrada.

## Contenido

- **Modo actual** (`mock` o `real`, leído del header `X-Chain-Mode`). Los escenarios automáticos solo se habilitan en `mock`. En `real` se pueden consultar las vistas y usar los formularios habituales con montos explícitos.
- **Escenarios**, todos por la API pública existente:
  1. Pago exprés a un trabajador (15 min, $18.000, 50 % fondeado).
  2. Pago exprés en lote a todos los trabajadores.
  3. Recargar el último pago activo (25 % del total, sin pasar el máximo).
  4. El trabajador retira la mitad de lo disponible a su wallet.
  5. Cancelar el último pago activo.
  6. Reiniciar datos demo (solo `mock`).
- **Registro** de cada acción con resultado, hash (link a Arbiscan si es onchain) o error.
- **Vistas en vivo**: `/worker` en un marco de 390 × 844 y `/payer` al lado. Se recargan después de cada acción. Un selector define qué trabajador muestra el celular.

## Decisiones

- `POST /api/lab/reset` reinicia el backend en memoria con `resetMockBackend()` de `lib/db/runtime.ts`. En `real` responde 404 y no toca nada.
- El Lab usa el mismo cliente de API que la UI; no agrega atajos de backend salvo el reinicio.

## Criterios de aceptación

1. En `mock`, cada escenario actualiza las dos vistas y deja una línea en el registro.
2. El reinicio vuelve a los dos pagos sembrados.
3. Lint, tipos, tests y build en verde.
